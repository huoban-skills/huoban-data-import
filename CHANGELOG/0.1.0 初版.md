# 0.1.0 初版

> 2026-08-28

把 Excel/CSV 导入伙伴云已有表时，难点在关联字段能否指向正确的现有数据。初版把匹配现状前置量化、交人裁决，再走官方导入通道写入。

## 摘要

1. 新增: 两阶段流程——先定拆分与数据主键并停下让用户确认，再做三层评估、出《导入方案》、执行到收尾
2. 新增: 《导入方案》是一份活文档，评估结果与执行清单两章贯穿全程，首版就交出去，确认回来复检后填定条数
3. 新增: 两个只读脚本——源文件体检判重、源主键与关联表比对出三档计数和待导入/疑似匹配 Excel
4. 新增: 交付目录三层——根放方案，`待导入/` 放核对后可直接导的，`待确认/` 放要逐条裁决的，`源文件/` 放底稿
5. 新增: 主键判定收录平台约束——自增编号和文本计算字段不能作导入目标，编号要用临时文本字段承载

---

## 详情

### 1. 新增: 两阶段流程

阶段一读源文件与工作区现状，产出「导入表拆分」与「匹配机制」两张表（按目标表分块，一表一个数据主键与关联匹配表），停下只问拆分是否合理、主键是否正确。阶段二做三层评估：源表层查主键重复，配置层查列映射、字段缺失、必填冲突、选项值、格式变形，数据层把源主键与关联表现有数据比对。导入方式固定 create，写入只走 `hac table +import-file`，本地解析只用于评估和生成清洗文件。

### 2. 新增: 《导入方案》活文档

一份文档两章：「评估结果」列概览与待确认内容（重复数据、名称对不上、需新建），「执行清单」列导入总览、系统改动（按表分块）、补索引、执行次序。首版交出时导入总览标"待确认后填定"，确认结果回来复检后填定；执行中任何变动当场同步进方案，待确认清空且全量核对通过即收尾。方案是唯一事实源，不存在只在对话里说了、方案里没有的决定。

关键取舍：待处理清单曾是独立文件、先于方案交出，定稿改为并入方案首版一次交出，避免两份文件互相引用、条数对不上。

### 3. 新增: 评估脚本

- `get_source_profile.py`：列清单、行数、空值率，按主键判重并导出标黄明细。
- `render_match_report.py`：源主键与关联表导出比对，输出可匹配 / 相似待确认 / 完全无三档；`--const` 给源文件注入主键需要但源表没有的维度（如单位类型），`--drop-blank-keys` 让选填关联跳过空键行。疑似匹配与待导入 Excel 都是双 sheet：明细在前抽源表行对照（疑似列标黄），结论一个主键一行，疑似匹配的确认结果列下拉只判"和系统那条是不是同一个"。
- 关联表数据用 `list-items` 分页拉取落本地，`+export` 是写风险命令不用于纯读链路。

### 4. 新增: 交付目录

```
〈项目〉-〈主题〉导入/
  导入方案.md
  待导入/      核对后可直接导的 Excel
  待确认/      要逐条裁决的 Excel
  源文件/      原始文件副本、关联表快照、回传
```

### 5. 新增: 主键判定的平台约束

编号字段是自增编号或文本计算时，服务端拦截导入写入，源文件里的编号要存到临时文本字段（如「旧-编号」）；主键用目标表字段原名，关联字段不嵌套展开。
