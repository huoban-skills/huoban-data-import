# 0.2.0 首次实战执行沉淀

> 2026-09-03

第一次在真实工作区跑通全程（两千多行源数据、五张表），执行期发现的平台行为和两次返工的原因落进规则。

## 摘要

1. 修复: 关联表快照必须按每页 50 条步进拉全——按 100 步进会漏一半，快照残缺让"系统里没有"判大，补数导入建出重复
2. 修复: 关联字段的数据源筛选是匹配前提——新建的关联记录不填筛选涉及的字段进不了候选，导入照样报无法匹配
3. 新增: 待导入文件用 `--carry` 带出能映射到关联表的源列，只导主键会漏字段
4. 新增: calculation 索引字段建法与日期格式口径
5. 新增: 表结构一变 import run 就过期，换文件名重新 prepare；`--judged-new` 让复检跳过已裁决新建的键
6. 新增: 脚本支持 .xls

---

## 详情

### 1. 修复: 关联表快照拉全

`list-items` 每页最多返回 50 条，`--limit 100` 也只给 50。翻页必须按上一页实际返回条数步进，加 `--order '{"item_id":"asc"}'` 稳定排序，返回不足 50 条才算到底，拉完再用另一种方式抽样核对总数。

改前 → 改后：`offset += 100` → `offset += len(本页返回)`。

### 2. 修复: 关联字段筛选当作匹配前提

评估时先读关联字段的 `config.filter`（如 合作状态=合作中、售卖状态=在售），关联表现有记录里不满足筛选的按"匹配不上"计；补关联数据时新建记录必须把筛选涉及的字段一并填上。多选字段的 `eq` 按精确相等比对，多角色记录进不了单角色筛选的候选，这种情况要么放宽筛选（用户拍板），要么按新身份单独新增。

### 3. 新增: 待导入带出可映射的源列

`render_match_report.py --carry 列名,...`：待导入结论 sheet 随主键带出指定源列，同一主键多值用「；」连接。生成待导入前对照配置层的列映射，源文件有、关联表也有的字段都要带上。

### 4. 新增: calculation 索引字段口径

`field-config init` 时补 `--patch '{"display_type":"input"}'` 才是文本型，否则 CONCAT 结果为空；`TEXT(日期)` 输出 `YYYY-MM-DD 00:00:00`，源侧索引列按此格式生成；关联表主记录字段可用 `direct:<关联字段>:<字段>` 引用。

### 5. 新增: import run 生命周期

目标表或关联表结构一变，已 prepare 的 run 的 plan 就过期（`IMPORT_PLAN_STALE`），revise/confirm 会互相打架，直接换文件名重新 prepare 最省事；同名文件对同一表存在未终结 run 时 prepare 冲突（`IMPORT_PROCESS_CONFLICT`）。update 模式只用于修补本批自己建的记录，`--update-by` 指定复合依据。`render_match_report.py --judged-new 文件`：回传裁决为"不是同一个"的源主键直接归入完全无，复检时不再被抓成疑似。

### 6. 新增: .xls 支持

`_common.read_rows` 通过 xlrd 读 .xls，数值整数去 `.0`，日期转 ISO。

### 文件结构
