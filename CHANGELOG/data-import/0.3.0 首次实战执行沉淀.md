# 0.3.0 首次实战执行沉淀

向璋医院备案导入（2265 行、5 张表）跑通全程后落进 skill 的规则：

- 关联表快照必须完整：`list-items` 每页最多 50 条，按实际返回条数步进、`--order '{"item_id":"asc"}'` 稳定排序、拉完交叉核对总数。快照残缺会把"系统里没有"判大，补数导入建出重复。
- 关联字段的 `config.filter` 是匹配前提：评估时按筛选口径算候选，补关联数据时新建记录必须填上筛选涉及的字段；多选字段的 `eq` 按精确相等比对，多角色记录进不了单角色筛选的候选。
- 待导入文件带出所有能映射到关联表的源列（`--carry`），只导主键会漏字段。
- calculation 索引字段要在 init 时补 `display_type=input` 才是文本型，否则 CONCAT 结果为空；TEXT(日期) 输出 `YYYY-MM-DD 00:00:00`，源侧索引列按此格式生成。
- 目标表或关联表结构一变，已 prepare 的 import run 的 plan 就过期，revise/confirm 会互相打架；直接换文件名重新 prepare 一个新 run 最省事。同名文件对同一表存在未终结 run 时 prepare 会冲突。
- update 模式导入用 `--update-by` 指定复合依据，只用于修补本次导入自己建的记录。
- 脚本 `_common.py` 支持 .xls（xlrd）；`render_match_report.py` 新增 `--judged-new`、`--carry`。
