# 三层评估

用户确认拆分与主键之后做。每层的发现都记进待处理清单，当场不改。

## 源表层：源文件内主键重复

按确认后的主键，对每一批拆分后的数据分组计数。

```bash
python3 scripts/get_source_profile.py --source '<源文件绝对路径>' --key '单位类型,单位名称'
```

重复分两种，处理方式不同：

- **整行完全重复**：源文件里的冗余，去重后导入即可，清单里说明去掉了多少条。
- **主键相同但其他列不同**：真冲突，无法自动判断留哪条。在副本 Excel 里标记出这些组，清单记条数与两三条样例，留待裁决。

主键相同的行如果超过总量的 5%，先回头质疑主键是不是定窄了，再发起数据修改。

## 配置层

### 列名到字段名的映射

源文件的列名和目标表的字段名往往不一致（同义不同名、带单位后缀、简称全称）。服务端 prepare 会自动匹配一版，但自动匹配只认名称相近，遇到下面几种会出错：

- 目标表有两个名字相近的字段，源列被匹配到其中错的那个。
- 源列名和字段名完全不像，自动匹配漏掉，这一列被静默丢弃。
- 源文件有两列语义相同（比如"产品名称"和"药品名称"），都匹配到同一个字段，后一列覆盖前一列。

所以评估时先把对应关系逐列列出来，源列名、目标字段名、是否导入，三栏对照。对不上的和不导入的都写清楚，这份对照表就是 prepare 之后核对 `auto_matches` 的依据。

### 目标表字段缺失

对比源文件列与目标表字段，找出源文件有、目标表没有的。

缺失不一定要补字段。判断标准是**这个值将来会不会变，变了要不要跟着变**：

- 值随关联表变化，业务上也应该跟着变：不补字段，用关联字段的附加显示带出来即可。
- 值是业务发生当时的快照，已发生的业务不应因基础数据后续改动而变（价格、扣率、当时的负责人）：必须提醒用户新增独立字段存快照，不能靠附加显示。

判断不确定时按快照处理，因为附加显示改成独立字段容易，反过来会丢历史。

### 关联表缺导入索引

主键是多字段组合时，关联表里要有一个字段承载拼接后的索引值，导入时映射到它。

- 优先 calculation 字段：拼接同表已有字段，值自动维护，不需要后续运维。建法走 `huoban-table` 的 `references/workflows/field-calculation.md`，不要手写字段 JSON。
- 拼接不出来时（要跨表取值、要条件判断、要引用关联表更深层的字段）只加文本字段，在导入目标表**之前**先把索引值刷进去，并在清单里提醒：这张表如果要长期反复导入，需要补一条自动化来维护这个索引字段，否则以后新增的数据没有索引，下次导入照样匹配不上。

源文件侧同样要加索引列，两侧归一化规则必须一致：去首尾空格、全角转半角、统一括号形态、去掉分隔符本身可能出现在值里的情况（值里含全角竖线时换用别的分隔符）。

### 必填冲突

读目标表的写 schema，找出必填字段。

```bash
hac table +schema --table '<表名或TABLE_ID>' --mode write
```

源文件对应列存在空值、且业务上确实允许为空时，需要先把系统必填取消。清单记表、字段、说明，并注明导入完成后是否要恢复必填（这个要问用户，不要自己决定）。

### 选项值映射

category 类字段的取值必须落在已有选项里。把源文件该列的去重值列出来，逐个比对目标表选项。

对不上的分两类：源文件写法与选项文案不一致（比如多了空格、简称全称不同），归入清洗；源文件出现了系统里没有的新选项，要问用户是加选项还是改数据。

导入时 Excel 值不在选项里的行为（报错还是自动新增选项）以 prepare 返回的 `configuration_guide` 为准，不要凭印象假定。

### 格式变形

三类最容易静默出错，逐列核对：

- **日期**：源文件是文本还是日期类型，格式是不是统一。Excel 里显示成 `2026-01-01` 但实际是文本的，导入可能失败或错位。
- **百分比**：伙伴云百分比字段传的是内部小数（如 `0.25`），apply 时按 25 提交。源文件如果已经是 `25` 或带 `%` 号，必须先换算，否则数值会差 100 倍。
- **数值**：千分位逗号、货币符号、括号表示负数、文本型数字，导入前都要清掉。

## 数据层：关联匹配现状

对每个必填关联字段，先把关联表现有数据导出到本地，再和源文件的主键比对。

先读关联字段的 `config.filter`：关联字段常带筛选（如 合作状态=合作中、售卖状态=在售、业务模式=某值），导入时只有满足筛选的关联表记录才是候选，名称对上但被筛选挡住照样报「无法匹配」。评估时要把筛选条件当作匹配前提：关联表现有记录里不满足筛选的按"匹配不上"计；补关联数据时新建记录必须把筛选涉及的字段一并填上，否则建了也对不上。

关联表数据用 `hac table list-items` 分页拉取落成本地 CSV（`+export` 是写风险命令要走确认，纯读链路不用它）。**接口每页最多返回 50 条，`--limit 100` 也只给 50；翻页必须按上一页实际返回条数步进，并加 `--order '{"item_id":"asc"}'` 稳定排序，返回不足 50 条才算到底。** 步进写错会让快照缺一半，后面所有"系统里没有"的判断都会失真、导入时新建出重复。拉完用一次不同方式（如按名称搜索几条）交叉核对条数。多选类型字段按顿号拆成多行再比对。

```bash
python3 scripts/render_match_report.py \
  --source '<源文件绝对路径>' --source-key '产品名称,产品规格' \
  --target '<关联表本地CSV>' --target-key '药品名称,规格' \
  --aux '生产厂家=生产厂家（上市持有人）' \
  --carry '生产厂家=生产厂家（上市持有人）' \
  --outdir '<输出目录>' --label '药品'
```

- `--const 列名=值`：源表没有但主键需要的维度（如单位类型）注入常量列；它参与匹配和展示（源主键列含它），只是不参与相似度打分。
- `--drop-blank-keys`：该关联本身选填时跳过主键含空列的源行，避免空值灌进待导入文件。
- `--carry 源列=关联表字段,...`：待导入文件随主键一起带出的源列，导入关联表时一并映射。**待导入不是只导主键**：生成前对照配置层的列映射，凡源文件有、关联表也有的字段全部带上（写 `all` 自动带同名列，异名的逐个写 `源列=关联表字段`）。漏带的字段导完要回头补更新，代价比一开始带上大得多。
- `--aux 源列=关联表字段,...`：疑似匹配文件里两侧并排展示的对照列，只供裁决时看，不参与相似判定。放什么由场景定：药品放厂家，单位放地址或联系人，员工放部门。
- `--judged-new 文件`：回传复检时传入已裁决为「不是同一个」的源主键清单（每行一个完整键），这些键直接归入完全无，不再被抓成疑似。
- 回传处理：判「是同一个」的把源值替换成系统写法生成清洗后源数据，判「不是同一个」的进已裁决清单，重复数据按裁决删行；复检以清洗后源数据跑，产物覆盖旧交付。回传解析三条规则：确认结果留空的按「不是同一个」处理，不猜；备注列里的疑问（"厂家一样吗"）要把两侧数据摆出来答复，答复前那条不动；判定与对照列明显矛盾的（判同一个但厂家不同、判不是但名称规格厂家全同）单独列出来请用户复核，不照单执行。
- 疑似匹配与待导入 Excel 都是双 sheet，明细在前：「明细」抽出涉及的源表行原样呈现；疑似匹配文件在主键字段旁插「疑似匹配·系统现有（关联表主键构成）」列（标黄）与相似度，表头直接写明键的构成；待导入文件把主键列标黄。「结论」一个主键一行、两侧完整主键，疑似匹配文件的确认结果列只判一件事：和系统那条是不是同一个（下拉二选一）。是同一个的按系统值导入，不是的按源文件值新建；本 skill 不修改已有数据，待导入文件即待新建清单，末列「导入索引」与关联表补索引字段同名同值（文本索引直接映射，calculation 索引作核对参照）。相似度只按真实主键部分计算，注入的常量维度不参与打分。

产出三档计数：

| 档 | 含义 | 后续动作 |
| -- | -- | -- |
| 可匹配 | 归一化后完全一致 | 无需处理 |
| 相似待确认 | 按下面的口径判为相似 | 生成疑似匹配 Excel，附疑似项、相似度与对照列，逐条裁决 |
| 完全无 | 关联表里找不到任何相近的 | 生成关联表待导入 Excel，确认后先导关联表 |

相似的口径与业务无关，只看主键各段的文本形态（实现在 `_common.py` 的 `keys_similar`）：

- 两侧主键**逐段**比对，每一段先归一化（全角半角、空白、大小写、×/x 统一成 *）。
- 一段算**等价**：归一化后相同；或去掉括号里的修饰语后相同（"小柴胡颗粒（无蔗糖）"与"小柴胡颗粒"）；或数字等价，即数字序列相同、或首个数字相同且其余数字乘积相同（"2mg*28s"与"2mg*7片*4板"）。
- 一段算**相似**：去括号后一方包含另一方；或相似度过 `--cutoff`（默认 0.75）。
- 多段主键：每一段至少相似，且至少一段等价，才算相似待确认。同名不同规格、同规格错字都会被抓到。单段主键只有相似度可依，过阈值即算。
- 判定不看厂家、状态这类业务字段，它们只作对照列展示；哪些列作对照由场景定（`--aux`）。

这个口径宁可宽：疑似列表长一点由人裁决，比漏到待导入建出重复便宜得多。

先把三档数字给用户看，再决定要不要继续。脚本对匹配率过低会给出警告，出现警告时先回头查索引拼接规则和主键定义，查完再交出清单。

同时检查关联表主键自身是否重复，重复的处理见 `keys-and-split.md`。
