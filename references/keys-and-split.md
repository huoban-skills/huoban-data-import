# 主键判定与拆分规则

本文用于定每张表的数据主键和一份源文件的拆分次序：先按「主键判定」序贯取键，再用「什么能进主键」逐字段校验，最后按「拆分」定导入顺序。

主键：导入时把一行 Excel 定位到系统里唯一一条数据的字段组合，写作 `字段A｜字段B`，用于源文件内判重和关联字段匹配。两侧（源文件列与关联表字段）用同一套归一化规则拼出完全一致的字符串。用户没说主键时自己判断，给出唯一推荐加一句话理由，让用户确认。

产出物里的写法：主键字段一律用**目标表字段原名**，不用源文件列名。关联字段进主键就直接写关联字段名（如 `对应药品`），它的匹配依据由关联匹配表单独承载，不在主键里嵌套展开关联表的主键。源列到字段的对应关系属于阶段二配置层。

## 一、主键判定

> 按序尝试，取到即止

| 序 | 规则 | 信号 | 动作 | 例子 |
| -- | -- | -- | -- | -- |
| 1 | 用已有业务编号 | 系统里有编号/单号类字段，且源文件该列非空 | 先查字段类型再用：文本类字段直接用，两边不用补索引；自增编号、文本计算字段的值由系统生成，服务端拦截导入写入，Excel 的编号进不去，需在表里临时加一个文本字段承载编号值，导入时写入它，别的表导入时也用它匹配 | 协议编号、客户税号 |
| 2 | 最小字段组合 | 没有编号 | 从最像名称的字段起，逐个加区分维度，直到在关联表现有数据上分组计数不再重复 | 单位类型｜单位名称 |
| 3 | 验证兜底 | 能区分业务实体的维度都加进来了，分组计数还有重复 | 重复的不是维度不够，是关联表里同一实体存了多条，转"关联表主键重复" | |

## 二、什么能进主键

| 判断 | 信号 | 例子 |
| -- | -- | -- |
| 能进 | 区分不同业务实体的维度 | 同一单位的不同角色身份、同一产品的不同规格 |
| 不能进 | 同一条实体身上会变的属性 | 状态、金额、数量、最近更新时间 |
| 按业务口径定 | 时间区间类字段：不同区间在业务上是不同记录时能进，只是同一条记录的属性时不进 | 同一医院同一药品的两个有效期是两份协议 → 能进 |

按业务口径拿不准时问用户。

## 三、关联表主键重复

关联表自己的数据按主键就有重复时，匹配会随机命中其中一条。两条路的代价说清楚让用户选，选择结果写进阶段一产出物：

| 方案 | 动作 | 代价 |
| -- | -- | -- |
| 合并关联表 | 重复条目合成一条，多出来的维度改多选字段 | 要改已有业务数据，历史单据引用的条目要一并处理 |
| 随便关联一条 | 关联表不动，接受随机命中 | 只适用于该关联不参与计算的场景；按这个维度统计时数据会拆成多份 |

## 四、拆分

> 一份 Excel 对应系统里几张表、什么顺序导

| 步 | 动作 | 依据 |
| -- | -- | -- |
| 1 | 画依赖 | 目标表 A 的关联字段指向表 B，B 先导 |
| 2 | 定次序 | 被关联的在前；同层按数据量从小到大，先导小的方便试错 |
| 3 | 算数据量 | 按该表主键去重后的条数；同一份 Excel 多行可能对应一张表的同一条数据 |
| 4 | 写导入说明 | 这一批取源文件的哪些行列、去重规则、为什么排这个位置 |
